# Product Requirements Document (PRD)

## Student Feedback Analysis Using Natural Language Processing

**Project Type:** NLP Academic Project
**Domain:** Education / Student Analytics
**Primary Technology:** Python, NLP, Machine Learning
**Dataset:** 5,000-record synthetic student feedback dataset
**Target NLP Tasks:** Text preprocessing, feature extraction, sentiment classification and analysis

---

## 1. Project Title

### **Student Feedback Analysis Using Natural Language Processing**

---

## 2. Project Overview

The proposed project is an **NLP-based Student Feedback Analysis System** designed to process and analyze textual feedback provided by students. The system applies Natural Language Processing techniques to convert unstructured textual feedback into meaningful information such as sentiment, frequently occurring terms, and feedback patterns.

The project uses a dataset containing **5,000 student records**, where each record is associated with a `Student_ID`, textual `Feedback`, and a sentiment label. The feedback dataset has been synthetically generated for academic/project demonstration purposes and contains **Positive, Neutral, and Negative** feedback categories.

The system will demonstrate important concepts from the NLP syllabus, including **text preprocessing, tokenization, stopword removal, stemming/lemmatization, Bag-of-Words/TF-IDF representation, sentiment analysis, and text classification**.

---

# 3. Problem Statement

Educational institutions collect large amounts of student feedback, but manually reading and analyzing thousands of comments is time-consuming and difficult.

For example:

> "The practical sessions are very helpful, but some topics need more explanation."

and

> "I am struggling to understand some of the concepts in this course."

contain useful information, but conventional numerical analysis cannot directly understand the meaning of such text.

Therefore, there is a need for an NLP-based system that can automatically process student feedback and categorize it into meaningful sentiment classes.

---

# 4. Objectives

The main objectives are:

1. To develop an NLP pipeline for processing student feedback.
2. To clean and normalize unstructured textual data.
3. To perform tokenization and remove unnecessary words.
4. To apply stemming or lemmatization.
5. To convert textual data into numerical representations using **Bag of Words and/or TF-IDF**.
6. To perform sentiment classification.
7. To classify feedback as:

   * Positive
   * Neutral
   * Negative
8. To identify frequently occurring words and patterns.
9. To evaluate the performance of the NLP classification model.
10. To provide visual representations of sentiment and word-frequency patterns.

## FR-03: Text Cleaning

The system shall clean the raw feedback by:

* Converting text to lowercase
* Removing unnecessary punctuation
* Removing unwanted special characters
* Removing extra whitespace
* Handling missing text

Example:

```text
"I Really Enjoy the Course!!!"
```

becomes:

```text
"i really enjoy the course"
```

---

# 7. NLP Processing Pipeline

The main NLP pipeline shall be:

```text
Raw Student Feedback
          ↓
      Text Cleaning
          ↓
      Tokenization
          ↓
     Stopword Removal
          ↓
 Stemming / Lemmatization
          ↓
 Feature Extraction
          ↓
   Sentiment Classification
          ↓
 Positive / Neutral / Negative
          ↓
       Evaluation
```

---

## FR-04: Tokenization

The system shall divide sentences into individual tokens.

Example:

```text
"I enjoy the practical sessions"
```

becomes:

```text
["I", "enjoy", "the", "practical", "sessions"]
```

---

## FR-05: Stopword Removal

Common words that provide little value for classification may be removed.

Example:

```text
"I enjoy the practical sessions"
```

may become:

```text
["enjoy", "practical", "sessions"]
```

---

## FR-06: Stemming / Lemmatization

The system may apply stemming or lemmatization to reduce words to their base forms.

Example:

```text
studying
studies
studied
```

can be transformed toward:

```text
study
```

The project should compare or document the selected approach.

---

# 8. Feature Extraction

The system should convert text into numerical vectors because machine-learning algorithms cannot directly process raw sentences.

### Option 1: Bag of Words

Represent each feedback text based on word occurrence.

### Option 2: TF-IDF ⭐ Recommended

Use **Term Frequency–Inverse Document Frequency** to determine the importance of words within the feedback corpus.

The primary implementation should use:

> **TF-IDF**

while Bag of Words can be included as a comparison.

---

# 9. Sentiment Classification

The system shall classify feedback into:

```text
Positive
Neutral
Negative
```

A suitable machine-learning classifier can be used after TF-IDF feature extraction.

Recommended models:

* Logistic Regression ⭐
* Multinomial Naive Bayes
* Support Vector Machine

### Recommended primary model

**Logistic Regression + TF-IDF**

Pipeline:

```text
Feedback
   ↓
Preprocessing
   ↓
TF-IDF
   ↓
Logistic Regression
   ↓
Sentiment
```

This also provides a clear connection between your **NLP syllabus and machine-learning-based text classification**.

---

# 10. Model Training

The dataset shall be divided into training and testing sets.

Recommended:

```text
80% → Training
20% → Testing
```

Therefore:

```text
Training = 4,000 records
Testing  = 1,000 records
```

A **stratified split** should be used so that the Positive, Neutral, and Negative classes maintain approximately similar proportions in training and testing data.

---

# 11. Model Evaluation

The system shall evaluate the classifier using:

### Accuracy

Measures overall correct predictions.

### Precision

Measures how many predicted samples of a class are actually correct.

### Recall

Measures how many actual samples of a class were correctly identified.

### F1-Score

Provides a balance between precision and recall.

### Confusion Matrix

Shows:

```text
                 Predicted
              P      N      Neg
Actual P
Actual N
Actual Neg
```

The project should report:

* Accuracy
* Precision
* Recall
* F1-score
* Confusion matrix

# 18. Non-Functional Requirements

The system should handle:

* Missing values
* Unexpected characters
* Very short feedback

without crashing.

The NLP pipeline should be divided into separate modules rather than placing the entire implementation in one large file.

A fixed `random_state` should be used during dataset splitting and model experiments where appropriate.
